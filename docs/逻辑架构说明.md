# 逻辑架构说明

## 1. 总览

本系统是房源推荐与可视化平台，采用前后端分离架构：
- 前端：Vue 3 + Vite，负责页面展示、交互、地图可视化和 API 调用。
- 后端：Spring Boot 提供 REST API，承载用户、搜索、推荐、预测、热力图等服务。
- 数据与计算：MySQL 存储业务数据；Hadoop HDFS 作为离线数据存储；Spark 批处理计算相似度、热力图数据及部分离线特征；Python 模型用于房价预测。

## 2. 核心组件

- 前端 Web 层：页面（登录、搜索、Tools/热力图等）、组件（房源卡片、偏好设置）、状态管理（Pinia）、路由、Axios 调用后端。
- API 网关/控制层：Spring Boot Controller（登录、资料、查询、推荐“其他用户也在看”、主页推荐等）。
- 业务服务层：
  - PropertySimilarityService / UserSimilarityService：调度或读取离线计算结果，必要时提供降级逻辑。
  - Predict 模块：房价预测，调用 Python 模型脚本（多城市配置）。
  - 其他领域服务：用户、房源、收藏、查询等。
- 批处理/离线计算：
  - Spark Batch Jobs（PropertySimilarityBatchJob、UserSimilarityBatchJob）：在 HDFS 上对海量对局/房源行为数据进行特征工程与相似度计算。
  - 输出表：property_similarity、user_similarity 等预计算结果（MySQL + HDFS 备份）。
- 数据层：
  - MySQL：主业务库，存储用户、房源、行为、预计算推荐结果等。
  - HDFS：离线数据湖，存放原始/中间数据及 Parquet/CSV/JSON 输出。
- 外部服务：高德地图 JS API 用于前端热力图与地图展示。

## 3. 主要流程

- 用户与权限：注册/登录，获取 Token 后访问受限接口；资料与偏好管理。
- 搜索与浏览：前端调用搜索/查询接口，后端从 MySQL 读取房源与预计算特征返回列表与详情。
- 推荐（“其他用户也在看”）：
  1) Spark 离线批处理生成 property_similarity 与 user_similarity。
  2) Controller 读取预计算结果按用户或房源召回并排序，返回前端。
- 房价预测：前端提交城市与特征，后端调用 Python 脚本/模型预测房价并返回结果。
- 热力图：Spark 批量汇总区域房价指标，结果存储 MySQL/HDFS；前端调用接口获取网格/点数据，用高德地图渲染热力图。
- 数据更新与调度：
  - 定时任务（@Scheduled）在凌晨触发 Spark Batch Job，完成离线重算与落库。
  - 手动触发与监控可通过服务层/工具类实现。

## 4. 数据处理与算法要点（Data Processing & Algorithms）

- 数据管线与质量：
  - 数据源：房源/小区/交易/用户行为（浏览、收藏、评分）；定期从 HDFS/MySQL 拉取并落盘。
  - 预处理：缺失值填充（均值/众数/中位数）、异常值裁剪（价格/面积分位数），时间戳标准化，坐标清洗与纠偏。
  - 样本策略：热门房源欠采样、长尾房源保留；行为去重与时间衰减；冷启动回退到基于内容/地理的召回。
  - 数据校验：行数对齐、字段分布监控（均值/方差/分位数），防止跑批前后分布漂移。
- 特征工程：
  - 基础特征：价格、面积、户型、楼层、朝向、建成年份、装修、学区、物业类型、分桶特征（价格/楼层/房龄）。
  - 位置特征：GeoHash 编码；行政区/商圈分桶；Haversine 距离、周边设施密度（可扩展 POI 特征）。
  - 时间特征：挂牌天数/更新时间的衰减权重，新房/热销房单独权重；可扩展季节性周期信号。
  - 交互特征：价格/面积比、楼层/总楼层比、房间密度、房龄分段、价格分档、区域均价对比差值。
  - 归一化与加权：关键特征标准化；按业务重要度调权；分城市独立缩放。
- 相似度计算（房源）：
  - 内容相似：特征向量余弦/欧氏，关键特征加权；可选标准化与温度缩放。
  - 地理相似：Haversine 距离 + GeoHash 粗定位；同区/邻区优先，距离阈值裁剪控复杂度。
  - 协同过滤：用户-房源行为矩阵；可扩展矩阵分解/隐语义；行为加权（浏览<收藏<评分）。
  - 混合相似度：内容(≈60%)+地理(≈25%)+协同(≈15%) 加权，可调参；多样性惩罚避免同质化。
  - 分层计算：粗排（GeoHash + 价格/面积桶 + 热度过滤）→ 精排（混合相似度 + 多样性惩罚 + 新鲜度权重）。
- 用户相似度：
  - 行为向量：浏览/收藏/评分权重化，时间衰减；兴趣标签（户型、价格带、区域偏好）。
  - 协同 + 内容融合：相似用户→相似房源扩展；冷启动回退地理+热门+内容召回；支持偏好标签召回增强。
- 房价预测：
  - 多城市独立模型（Python）；输入经纬、面积、楼层、房龄、装修、学区、周边均价等核心特征。
  - 输出估价 + 置信度；可落库或直接返回；支持分城市模型版本管理与快速回滚。
- 热力图聚合：
  - 区域/网格统计均价、中位数、数量分布；可按时间窗口（周/月）生成多版本热力图；支持增量重算。
  - 数据存 MySQL/HDFS；前端按价格区间/时间切片拉取，用高德地图渲染；支持点/网格两种模式。

## 5. 性能与可用性（Performance & Reliability）

- 预计算与缓存：
  - 推荐/相似度、热力图聚合均离线预计算；在线接口直接读取 MySQL 结果或缓存，响应达秒级。
  - 前端/网关可启用短时缓存；热点接口可加本地缓存与限流，减压数据库；可选只读副本提升读吞吐。
- 分层推荐与召回：
  - 粗排用 GeoHash、价格/面积桶、热度阈值等快速裁剪，减少 70%+ 精排计算量。
  - 精排融合混合相似度与多样性约束；支持 Top-N 去重、价格/区域分布均衡；可插 AB 实验调权。
- 分布式批处理与资源调优：
  - Spark 支持 local/yarn；百万级房源 5-10 分钟批处理；通过分区数、并行度、executor 内存/核数调优吞吐。
  - HDFS 存储原始/中间/结果数据，支持增量/全量重算与回溯；按天/城分区管理以减少扫描。
- 地理优化：
  - Haversine 精确距离 + GeoHash 近邻索引；距离阈值/同区优先裁剪，降低复杂度。
  - 预留 KD-Tree/球面分桶扩展以支持更大规模地理检索；可对热门区域做局部索引缓存。
- 新鲜度、稳定性与降级：
  - 时间衰减保证推荐更新；定时跑批（凌晨）+ 手动触发；支持紧急重跑窗口。
  - 跑批失败/延迟：降级使用上一周期结果或实时简化规则（热门+地理近邻）；接口超时熔断与降级兜底。
- 监控与告警（可扩展）：
  - 跑批耗时、任务失败重试、数据量对齐校验；核心接口 QPS/延迟/错误率监控。
  - 推荐命中率/多样性、热力图数据新鲜度、房价预测命中分布可纳入质量监控；报警与自愈策略预留。
- 可扩展性与演进：
  - 前后端分离，独立部署与弹性扩容；批处理与在线服务解耦，便于独立伸缩。
  - 数据湖化（HDFS）便于追加新特征/模型；接口保持向后兼容，支持灰度、版本共存与快速回滚。

## 6. 运行与部署视角

- 开发：Spark local 模式，MySQL 本地，前后端分别 `npm run dev` / `mvn spring-boot:run`。
- 生产：Spark yarn 集群或独立集群，HDFS 正式集群，Spring Boot 部署至容器/主机，前端构建后静态托管；定时任务跑批并落库。
