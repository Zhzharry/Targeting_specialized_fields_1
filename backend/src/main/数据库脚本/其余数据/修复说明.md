# SQL脚本外键引用问题修复说明

## 问题原因

失败的SQL脚本（04-09）引用了不存在的 `user_id` 或 `property_id`，导致外键约束失败。

原因：
- SQL脚本中硬编码了ID（如 property_id=10, user_id=4等）
- 但实际数据库中的ID可能是自动递增的，不一定从这些值开始
- 外键约束检查导致插入失败

## 解决方案

### 方案1：使用Python脚本自动生成（推荐）

**步骤：**

1. 运行修复脚本：
```bash
cd backend/src/main/数据库脚本/其余数据
python 修复脚本_使用实际ID.py
```

2. 脚本会自动：
   - 查询数据库中实际存在的用户ID和房源ID
   - 生成修复后的SQL文件（*_fixed.sql）

3. 使用修复后的SQL文件：
```bash
# 方法1：直接执行修复后的文件
mysql -hlocalhost -P3306 -ubigdata_user -p123456 bigdata < 04_browsing_history_fixed.sql
mysql -hlocalhost -P3306 -ubigdata_user -p123456 bigdata < 05_favorites_fixed.sql
mysql -hlocalhost -P3306 -ubigdata_user -p123456 bigdata < 06_search_history_fixed.sql
mysql -hlocalhost -P3306 -ubigdata_user -p123456 bigdata < 07_user_preferences_fixed.sql
mysql -hlocalhost -P3306 -ubigdata_user -p123456 bigdata < 08_user_recommendations_fixed.sql
mysql -hlocalhost -P3306 -ubigdata_user -p123456 bigdata < 09_user_similarity_fixed.sql

# 方法2：或者更新一键注入脚本，使用修复后的文件
```

### 方案2：临时禁用外键检查

如果只是想快速插入数据，可以临时禁用外键检查：

```sql
USE `bigdata`;

-- 禁用外键检查
SET FOREIGN_KEY_CHECKS = 0;

-- 执行原来的SQL文件
SOURCE 04_browsing_history.sql;
SOURCE 05_favorites.sql;
SOURCE 06_search_history.sql;
SOURCE 07_user_preferences.sql;
SOURCE 08_user_recommendations.sql;
SOURCE 09_user_similarity.sql;

-- 恢复外键检查
SET FOREIGN_KEY_CHECKS = 1;
```

**注意：** 这种方法虽然可以插入数据，但可能会插入无效的外键引用，不推荐在生产环境使用。

### 方案3：手动查询并修改SQL

1. 查询实际存在的ID：
```sql
-- 查询用户ID
SELECT user_id, username FROM users ORDER BY user_id;

-- 查询房源ID
SELECT property_id FROM properties ORDER BY property_id;
```

2. 根据查询结果，手动修改SQL文件中的ID引用

## 预防措施

为了避免将来出现类似问题，建议：

1. **使用子查询**：在SQL中使用子查询来获取实际存在的ID
2. **使用Python脚本**：自动生成SQL，避免硬编码ID
3. **先查询后插入**：先查询存在的ID，再生成插入语句

## 注意事项

- 修复脚本会生成新的SQL文件，不会覆盖原文件
- 如果数据库中没有足够的用户或房源数据，修复脚本会提示错误
- 建议在执行修复前先备份数据库
